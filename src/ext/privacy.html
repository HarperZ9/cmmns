Radar privacy policy

Updated 2026-10-21.

Radar runs entirely in your browser. It has no server, no account, no analytics and no telemetry. Nothing Radar reads or works out is sent to the author. One feature, Other coverage, sends the main words of an article's title to the GDELT Project, and only when you turn it on and click; it is off by default and described below.

What Radar reads

Radar reads what the site you are on has already shown or loaded for you: the replies on the page, the account details the site discloses (for example X's "About this account" label), and the post data the site's own app downloaded. It reads nothing the site does not show its viewers, and never reads IP addresses.

Requests Radar makes

Radar sends no data to the author, to analytics services or to any server of its own. It makes these requests, all to the site you are already using, with that site's own session in your browser:

SiteRequestWhen
XThe "About this account" data for reply authors, through the same request X's own app makes, at most one account every 1.5 seconds and slower when X says it is busyAutomatically, unless you switch off "Read account details automatically"
XOne account's profile and About page in a minimised window, so Radar can learn X's request the first time, or when you ask Radar to read accountsThe first time, and when you ask
RedditReddit's public account data (/user/<name>/about.json) for comment authors, one account every 2 secondsAutomatically, unless you switch that setting off

On Bluesky, Threads, TikTok and Mastodon servers Radar makes no request at all: it reads the page and copies responses the site's own app already loaded (on TikTok and Mastodon, the comment and thread lists; Radar never reads request headers or login tokens).

Mastodon servers. Radar has no access to any Mastodon server until you turn it on for that server. When you open Radar's toolbar button on a page Radar does not run on, it checks two things on that page only: whether it is the Mastodon web app, and the app's version and domain. If it is, the button offers "Turn on Radar here", and your browser asks you to allow access to that one server. The list of servers you turned on is kept in pb.instances.v1; Options, Mastodon servers, Remove takes the access back.

Fact-check matching runs against a table bundled inside Radar, so post text is never sent to a fact-checking service. Site cards (owner, owner type, founding date, country, state links and a site's fact-check record) come from tables bundled inside Radar too, on links, on search results when you turn an engine on, and on the page you are reading when you press "Site card for this page". None of these send anything.

Other coverage (off by default)

Other coverage is off unless you turn it on in the options page. When it is on and you click "Find other coverage" on an article's site card, Radar sends the main words of that article's title, and nothing else, to the GDELT Project's public DOC 2.0 API at api.gdeltproject.org. Radar does not send the page address, your history, any post or any account. GDELT receives the request like any web request, so it sees your IP address and the words; its terms are at gdeltproject.org. Before the first request the card shows the exact words it would send and waits for your click. Turning the option off withdraws the browser permission and resets that consent. Firefox also asks you to allow "website content" for this feature when you turn it on.

The window offers reverse image search links (Google Lens, TinEye, Bing, Yandex) for media. Those open only when you click one, and then that service receives the image address.

Media checks, only when you click. "Check this file" re-requests one image or video file the page already loaded, from the exact address the page used (for X, its own media server), without cookies, so the browser usually answers from its cache. Radar reads the file's Content Credentials and metadata in the tab and keeps the result in memory only. "Take 4 frames" copies frames from the page's own video player in the tab; choosing a search service then copies one frame to your clipboard and opens that service, which receives nothing until you paste the frame there. Credentials stored online (a file that points to a remote manifest) are never fetched.

Reading text in an image, off by default, only when you click. With "Read text in images" turned on in the options page, "Read text in this image" re-requests that one image the same way, from the address the page used and without cookies, and hands its bytes to Radar's own background worker in your browser. The words are read there by code and weights shipped inside Radar; nothing is downloaded for it. The image, the text and any hash of either never leave your browser. The text is kept in memory for that window only.

Everything is kept in chrome.storage.local (Firefox: browser.storage.local) in the browser profile you installed Radar in. It is not synced to other devices.

Post data from the page (views, posting app, media upload times) is held in memory for the tab and is gone when you close it.

Your controls

  • Options page: switch Radar off per site or pause it everywhere, change how long it keeps data, and press "Clear all Radar data" to delete everything above except your settings.
  • History page: clear the history, connections and trails on their own.
  • Save report: writes a JSON file to your computer only when you click it. It holds the thread report, account labels and flags, and leaves reply text out.
  • Save feedback to a file (options page): writes your marks to a JSON file on your computer only when you click it. Radar never sends it. You choose whether to share it, for example by attaching it to an issue on Radar's repository. "Clear feedback" deletes your marks.
  • Analyse a file: reads a saved page, thread JSON, a platform data export or a media file you choose, on your device. The file is not kept and nothing is sent.
  • Save signed bundle (Analyse a file and the thread card page): writes a JSON file to your computer only when you click it. It holds post ids, the evidence with the matched words, Radar's version, a hash of its data tables, the time and your bundle key's public half. Full post text goes in only if you tick the box. Radar never sends it.
  • Removing Radar deletes everything it kept.

What Radar never does

  • Sends anything to the author, or to a third party except the title words you send through Other coverage.
  • Sells, shares or uses data for advertising.
  • Guesses who runs an account, or anyone's age, gender, ethnicity, religion or politics.
  • Links accounts across sites.

Changes

Changes to this policy are listed in Radar's changelog with the version that made them.

Contact: open an issue on Radar's repository.
